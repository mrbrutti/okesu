## Summary

Phase 22.3 of the threatcaddy-borrows plan
(`docs/superpowers/specs/2026-04-29-threatcaddy-borrows-phasing-design.md`).

- New Investigation entity + CRUD endpoints. Operators can promote a
  finding into an investigation, link more findings/runs to it, write
  notes, and close it with a resolution.
- New `hypothesis` finding subtype + `hypothesis-writer` shared agent.
  Hypothesis findings carry structured `claim` / `evidence_for[]` /
  `evidence_against[]` / `confidence` / `how_to_test` attributes; UI
  renders a dedicated card.
- New `kind: meeting` orchestration step type. Sequential participants
  + synthesizer; each participant sees the trigger plus prior outputs.
  Synthesizer prompt-instructed to emit `meeting_minutes` findings.
- War-bridge variant: `war_bridge: true` on a meeting step instructs
  the synthesizer to tag the resulting finding `war-bridge`. Dashboard
  renders a red banner listing active war-bridge findings via a
  polling `/api/findings/war-bridge` endpoint.

## Files

- New tables: `investigations`, `investigation_findings`,
  `investigation_runs`, `investigation_notes` (migration 036).
- New finding column: `subtype` (also surfaced via `findingJSON`'s
  wire shape).
- New endpoints: `/api/investigations*`, `/api/findings/war-bridge`.
- New orchestration step kind: `meeting` (with `war_bridge` flag).
- New shared agent: `agents/hypothesis-writer.md`.
- New UI: Investigations list/detail, HypothesisCard, WarBridgeBanner,
  "Open in investigation" finding action.

## Open follow-ups

- Markdown rendering for investigation note bodies (v1 uses
  `whitespace-pre-wrap` plain text).
- Modal for the "Open in investigation" prompt (v1 uses
  `window.prompt()`).
- Federation propagation of investigations across CPs (v1: each CP has
  its own).
- `MeetingSpec.ContextWindow` is parsed and validated but not yet
  consumed; v1 always uses "trigger" (the default). Implementation
  for "trigger+last_5_findings" deferred to a future phase.
- Meeting `tags` mutation in `runMeetingStep` is a defensive fallback
  for env-binding; the DB tag relies on the agent following the
  prompt-baked instruction. A misbehaving LLM that ignores the
  instruction would not get its finding tagged at the DB layer.
