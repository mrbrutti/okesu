## Summary

Phase 22.1 of the threatcaddy-borrows plan
(`docs/superpowers/specs/2026-04-29-threatcaddy-borrows-phasing-design.md`).

- IOCs promoted to first-class CP entity (curated YAML catalog +
  observed DB population, auto-extracted at finding ingest).
- Orchestrator actions classified into read/enrich/fetch/create/modify
  with per-class auto-approve policy.
- Daemon scheduler supports `interval_min` / `interval_max` with
  geometric backoff on idle, reset on findings/error.
- Engine renders template strings in `data:` params (was a latent
  blocker for templated lookups like the rewritten t2-fleet-ioc-hunt).
- `t2-fleet-ioc-hunt` scope step now uses the new `iocs.lookup` data
  query instead of free-form regex validation.
