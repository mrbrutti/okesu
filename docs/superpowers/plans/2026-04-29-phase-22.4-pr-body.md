## Summary

Phase 22.4 of the threatcaddy-borrows plan
(`docs/superpowers/specs/2026-04-29-threatcaddy-borrows-phasing-design.md`).

- Cross-CP IOC pattern supervisor daimon ticks every 5 minutes on the
  parent CP and emits findings for IOCs hitting the configured
  observation threshold.
- New `enrich_ioc` orchestration action (class: enrich) fans out to
  VirusTotal / AbuseIPDB / Shodan with per-adapter rate limits, caches
  results in `ioc_enrichments` (TTL 24h default).
- Typed `ioc_relationships` graph (fixed v1 vocab) with read endpoint
  at `/api/iocs/{id}/relationships`.
- STIX 2.1 bundle export at `/api/stix2/iocs` for TIP interoperability
  (MISP, OpenCTI). Pattern values are escaped to handle URL IOCs with
  embedded quotes; malformed `?since` returns 400.

## Open follow-ups

- Federation-aware cross-CP semantics: today the parent CP rolls up
  observations from federated children via the existing IOC-observation
  flow; explicit per-child-CP attribution would require
  `cp_instance_id` on `ioc_observations`.
- STIX UUIDv5 ids (current v1 uses SHA-1 prefix slug — works but not
  canonical).
- STIX bundle pagination — current implementation has a hard 1000-IOC
  cap with no `Link: rel=next` header. Fine for v1 deployments but
  needs revisit before large-fleet rollout.
- Relationship `created_at` column on `ioc_relationships` (currently
  STIX SROs use export wall-clock, so `modified` differs across
  exports of the same logical edge).
- UI surface for relationships graph (v1 ships endpoints only).
