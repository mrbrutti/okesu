# Postgres migrations — placeholder

The CP currently embeds 18 migrations under `controlplane/db/migrations/`
written for SQLite. The Postgres backend (Phase 8b) connects cleanly to
managed Postgres but does NOT yet apply schema migrations against it —
that port lands in a follow-up.

When the port is done, the dialect-aware migration runner will load
files from this directory when `Dialect == DialectPostgres`. Until
then, operators wanting to run against Postgres should bootstrap the
schema externally (psql, sqlc, golang-migrate) using a port of the
SQLite SQL.

## Differences to handle when porting

- `INTEGER PRIMARY KEY AUTOINCREMENT` → `BIGSERIAL PRIMARY KEY` (or
  `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` if PG ≥ 10
  preferred)
- `INSERT OR IGNORE` → `INSERT ... ON CONFLICT DO NOTHING`
- `INSERT OR REPLACE` → `INSERT ... ON CONFLICT (...) DO UPDATE SET ...`
- `?` placeholders in Go code → `$1, $2, ...` (will be runtime-translated
  in a future commit; SQL files don't have placeholders)
- `strftime('%s', ts)` → `EXTRACT(EPOCH FROM ts)` — only used in a
  couple of aggregate queries (findings.go, see `KnownIssuesForAgent`
  and `LookupFindings`)
- `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` works in both but Postgres
  stores microseconds; SQLite stores second-precision. The Go `time`
  layer handles both.
- TEXT vs VARCHAR — TEXT is portable; we already use it.

The migration runner stays single-source for now; when this dir is
populated, `applyMigrations` will dispatch by dialect.
